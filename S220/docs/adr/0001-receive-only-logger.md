# ADR-0001: 受信専用のロガーとし、モジュール設定・送信機能を持たない

- ステータス: ADR-0012 により置換
- 日付: 2026-10-15

## コンテキスト

- 評価システムのハードウェアは、E220 の M0 / M1 を GND に直結して**ノーマルモード（トランスペアレント通信）に固定**している（[S220HW.md](../../../S220HW.md)）。この構成ではアプリからレジスタ設定を変更できない。
- PC 版の要件（[S220SW.md](../../../S220SW.md)）では「最終的に**受信側**を Android へ移植する」としていた。
- 評価の目的は、送信側（PC + `tx_app.py`）を固定し、受信側を持ち歩いて到達範囲と受信強度を測ることである。

## 決定

Android アプリは**受信と記録だけ**を行う。送信機能、E220 のレジスタ読み書き（設定モード）は実装しない。
モジュールの設定（RSSI バイト有効化など）は、PC の [`sample_code/config_gui.pyw`](../../../sample_code/config_gui.pyw) 等で事前に行う。

## 理由

- ハードウェアがノーマルモード固定のため、設定機能を実装しても使えない。
- 機能を受信・記録に絞ることで、屋外で片手で使える単純な UI にできる。
- 送信側は PC 版で既に実装済みで、評価に十分。

## 結果

- 画面は 1 つ、操作はメニューのみの簡素な構成になった。
- 利用者は事前に E220 の設定（RSSI バイト有効、アドレス・チャンネル・空中レートの一致）を済ませておく必要がある。仕様書の前提条件に明記した。
- 双方向通信（ACK による確実な到達確認）は評価できない。到達確認は `SEQ` 連番による欠落推定で代替する。

## 検討した代替案

- **送受信両対応**: 1 台の端末で往復の評価ができるが、UI と状態管理が複雑になり、評価目的に対して過剰。
- **設定モードの実装**: M0 / M1 を GPIO で制御する回路変更が必要。今回の評価範囲外。
