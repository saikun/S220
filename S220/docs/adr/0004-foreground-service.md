# ADR-0004: 受信・記録をフォアグラウンドサービスで実行する

- ステータス: 承認
- 日付: 2026-10-15

## コンテキスト

- 評価は端末をポケットに入れて歩き回りながら行う。画面 OFF や他アプリ（地図など）の使用中も受信・測位・記録を止めてはならない。
- Android は、バックグラウンドのアプリの CPU・位置情報アクセスを強く制限する（Doze、バックグラウンド位置制限）。
- 受信データの取りこぼしは評価結果（パケットロス）を直接ゆがめる。

## 決定

- USB 受信・処理・記録・GPS・音の一切を **`RxService`（フォアグラウンドサービス、`foregroundServiceType="location"`）** に置く。Activity は表示と操作だけを担当する。
- セッション中は **`PARTIAL_WAKE_LOCK`** を保持する（タイムアウト 24 時間。2026-10-16 から 1 時間ごとに取り直して延長）。
- 記録中であることを常駐通知で示し、通知から画面を開く・停止できるようにする。
- Activity → Service の操作は `Intent` の Action（`START` / `STOP` / `CONNECT` / `SET_SOUND`）で送る。サービスはバインドしない（`onBind` は `null`）。
- `START_NOT_STICKY` とし、システムによる再起動では記録を再開しない。

## 理由

- フォアグラウンドサービスはユーザーに見える形で実行されるため、OS に停止されにくく、location タイプを宣言すれば `ACCESS_BACKGROUND_LOCATION` なしで画面 OFF 中も位置を取得できる。
- `PARTIAL_WAKE_LOCK` がないと、画面 OFF 中に CPU が眠り USB の読み込みループが止まる。
- Intent のみで操作すると、Activity の破棄・再生成とサービスの生存期間を独立させやすい。
- 記録開始には保存先の選択が必要なため、保存先が分からないシステム再起動では再開しない方が安全。

## 結果

- 画面を閉じても記録が続き、通知に受信件数・最新 RSSI・USB 状態が出る。
- 電池消費が増える（GPS 1 秒間隔 + WakeLock）。評価用途として許容する。
- OS によるプロセス終了からの自動復帰には対応しない（[設計書 §11](../design.md#11-既知の制約と改善候補)）。
- 当初は WakeLock が 24 時間で切れていたが、2026-10-16 に定期的な取り直しを追加し、24 時間を超える連続記録に対応した。
- `targetSdk` を 34 以上に上げる際は、フォアグラウンドサービスの種別と権限の宣言を見直す必要がある。

## 検討した代替案

- **Activity 内で受信**: 画面 OFF・他アプリ使用中に止まるため要件を満たさない。
- **WorkManager**: 定期・遅延実行向けで、連続したストリーム受信には向かない。
- **`connectedDevice` タイプのフォアグラウンドサービス**: USB 機器との通信には本来こちらが適するが、`targetSdk 33` では不要で、位置情報の取得には `location` タイプが必要なため `location` を採用した。
