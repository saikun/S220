# ADR-0006: RSSI バイト付加を前提とし、無線パケット境界を UART 無出力 200 ms で判定する

- ステータス: 承認
- 日付: 2026-10-15

## コンテキスト

- 評価の主目的は受信強度（RSSI）の地理的分布を得ることである。
- E220 は「RSSI バイト」設定を有効にすると、受信データを UART に出力した後に 1 byte（dBm = 値 − 256）を続けて出力する。区切りやヘッダはない。
- UART からは任意の単位でデータが届くため、どこまでが 1 無線パケットか（＝末尾 1 byte がどこか）を受信側で判断する必要がある。
- AUX ピンは未接続で、モジュールの送受信状態は分からない（[S220HW.md](../../../S220HW.md)）。
- PC 版 `rx_app.py` は 80 ms、E220 サンプルの Windows 版 `operation_code_win/receive.py`（ラズパイ版の `sleep(0.200)` 相当）は 200 ms の無出力で 1 パケットとしている。

## 決定

- `MessageProcessor` を **`rssiEnabled = true` 固定**で使う（設定 UI は設けない）。
- UART 出力が **200 ms**（`RxConfig.DEFAULT_PACKET_GAP_MS`）途切れたら 1 無線パケットとして確定する（`PacketAssembler`）。
- パケット確定後に RSSI を分離し（[ADR-0007](0007-rssi-split-heuristic.md)）、残りを行分割へ渡す。
- 各行には、その行を完成させたパケットの RSSI（`lastRssi`）を付ける。RSSI を分離できなかったパケットでは `null` にする（2026-10-16 修正。以前は前回の値が残っていた）。

## 理由

- 評価用途では RSSI は必須で、毎回切り替える必要がない。設定項目を減らし、現場での設定ミスを防ぐ。
- 9600 bps では 1 byte ≈ 1 ms で連続出力されるため、同一パケット内で 200 ms 途切れることはない。80 ms より長く取ることで、**ペイロード出力と RSSI バイト出力の間の遅延**、および Android の USB 転送のばらつきを確実に吸収する。
- 実機で検証済みのサンプルコードと同じ値にそろえる。

## 結果

- E220 の RSSI バイトを有効にしておくことが利用の前提条件になった（仕様書に明記）。
- 受信から画面表示までに最低 200 ms の遅延が入る。
- **送信間隔が短く、2 つのパケットが 200 ms 以内に連続すると 1 パケットとして扱われる**。この場合、前のパケットの RSSI バイトが次の行の先頭に残り、RSSI は後ろのパケットの値のみ集計される。送信側は十分な間隔（`tx_app.py` の既定は 5 秒）で送る運用とする。
- 1 行が複数の無線パケットにまたがる場合（サブパケット長 200 byte 超）、その行の RSSI は最後のパケットの値になる。
- PC 版（80 ms）と値が異なる。PC 版も 200 ms にそろえるかは別途判断する。

## 検討した代替案

- **RSSI モードを設定で切り替え可能にする**: 柔軟だが、設定ミスで RSSI が取れない／本文が欠けるリスクがある。要望が出たら追加する。
- **AUX ピンで送受信完了を検出**: 最も確実だが回路変更が必要で、FT232RL 経由では AUX を読めない（モデム制御線への割り当てが必要）。
- **送信側でヘッダ（長さ）を付ける独自プロトコル**: 境界判定は確実になるが、任意のバイト列やサンプルコードの送信データを受信できなくなる。
