# ADR-0008: 位置情報に Android 標準の `LocationManager` を使う

- ステータス: 承認
- 日付: 2026-10-15

## コンテキスト

- 受信 1 件ごとに、その時点の位置を記録する必要がある。歩行速度でも地図上で区別できる程度（数 m〜十数 m）の精度と更新頻度が欲しい。
- 屋内・ビル陰など GNSS が届かない場所でも、おおよその位置は残したい。
- 評価用端末は Google Play 開発者サービスが入っているとは限らない（業務用端末、カスタム ROM など）。

## 決定

- `location/LocationTracker` で `LocationManager` を直接使う。
  - **GPS** を 1 秒間隔、**ネットワーク位置**を 5 秒間隔で要求（距離条件なし）。
  - コールバックは専用の `HandlerThread` で受ける。
- 現在位置 `current()` は、GPS が 10 秒以内なら GPS、そうでなければ GPS / ネットワークのうち新しい方を返す。
- 受信時にはその時点の位置を `GeoFix`（緯度・経度・高度・精度・プロバイダ・取得時刻・経過秒）としてスナップショットする。
- 移動軌跡 GPX には GPS プロバイダの位置のみを記録する。

## 理由

- Google Play 開発者サービスに依存せず、どの端末でも同じ動作になる。依存ライブラリも増えない。
- GPS を 1 秒間隔にすることで、受信時刻と位置の時間差を最小にできる。
- 位置の経過秒を一緒に記録することで、後から「どれだけ古い位置か」を評価できる（画面では 10 秒超を薄く表示）。

## 結果

- 屋内ではネットワーク位置で補完されるが、精度は低い（精度 `accuracy_m` を CSV / GPX に残す）。
- Fused Location Provider に比べ電池消費が大きく、測位の立ち上がりが遅い場合がある。
- API 24〜29 の `LocationListener` には既定実装がないため、`onStatusChanged` 等を明示的に実装している。

## 検討した代替案

- **Fused Location Provider（Google Play 開発者サービス）**: センサー融合で精度・電池効率が良いが、Play 開発者サービスへの依存が生じる。
- **GPS のみ**: 屋内で位置が完全に欠ける。
