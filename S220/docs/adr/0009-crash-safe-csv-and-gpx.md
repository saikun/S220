# ADR-0009: ログを CSV と 2 種類の GPX に、中断に強い方式で逐次書き出す

- ステータス: 承認
- 日付: 2026-10-15

## コンテキスト

- 評価結果は、表計算での集計（受信率・RSSI 分布）と、地図上での可視化（どこで受信できたか）の両方に使う。
- 屋外での長時間記録中に、電池切れ・OS によるプロセス終了・USB や SD カードの抜けが起こり得る。途中で止まっても、それまでのデータは使える状態で残したい。
- 「受信できなかった場所」を知るには、受信地点だけでなく移動経路も必要。

## 決定

記録開始ごとに 3 ファイルを作る。

| ファイル | 形式 | 書き込み方式 |
| --- | --- | --- |
| `rx_<stamp>.csv` | 画面と同じ全行（RX / WARN / SYS）。UTF-8 BOM 付き、CRLF | 1 行ごとに `flush` |
| `rx_<stamp>_rssi.gpx` | 受信地点の `<wpt>`。`<name>` に RSSI、独自拡張 `s220:` に RSSI・段階・SEQ・本文・精度 | `RandomAccessFile` で閉じタグ直前に追記し、閉じタグを毎回書き直す |
| `rx_<stamp>_track.gpx` | GPS の移動軌跡 `<trk>` | 同上 |

GPX は前回記録点から **5 m 以上の移動、または 10 秒以上経過**したときのみ点を追加する（間引き）。
書き込み失敗は例外を握りつぶし、受信・表示は続ける。

## 理由

- **CSV** は Excel で直接開けて集計しやすい。BOM を付けて日本語の文字化けを防ぐ。1 行ごとの `flush` で、強制終了時も直前の行まで残る。
- **GPX** は Google マイマップ・Google Earth・各種 GIS で標準的に読める。`<name>` に RSSI を入れるとピンのラベルとしてそのまま表示される。
- GPX は XML のため、閉じタグがないと読み込めない。閉じタグを毎回書き直すことで、**どの時点で中断しても整形式**になる。
- 受信地点と軌跡を別ファイルにすると、地図ツールでレイヤーとして重ねたり、片方だけ表示したりできる。
- 静止中に短周期で受信すると同一地点に大量の点が重なり、地図ツールの読み込み上限や視認性の問題になるため間引く。

## 結果

- 中断しても 3 ファイルとも開ける状態で残る。
- 1 件ごとにファイルへ書き込むため I/O が多いが、LoRa の受信頻度（秒単位）では問題にならない。
- **GPX は間引かれるため、全受信の分析には CSV を使う**必要がある（統計行の「GPX: n点」は間引き後の点数）。
- 独自拡張の名前空間 URI は仮の値（`https://example.com/s220/gpx/1`）。
- 位置のない受信は RSSI GPX に記録されない（CSV には残る）。

## 検討した代替案

- **SQLite（Room）に保存し、エクスポート時に変換**: 検索・集計が柔軟だが、PC へ取り出すのにエクスポート操作が必要になり、中断時の扱いも複雑になる。
- **KML / GeoJSON**: 地図表示はできるが、GPX の方がトラックとウェイポイントを標準で扱え、対応ツールが多い。
- **終了時に一括書き出し**: 実装は簡単だが、異常終了時に全データを失う。
