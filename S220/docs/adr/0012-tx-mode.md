# ADR-0012: 送信モード（TX）を追加し、起動時に RX / TX を選ばせる

- ステータス: 承認
- 日付: 2026-10-16

## コンテキスト

- これまで送信側は PC + `tx_app.py`（普段は `python tx_app.py COM9 -f --address 0 --channel 0 --interval 3`）で運用していた。
- 送信側にも PC を置かずに済むよう、Android 端末 + FT232RL + E220 だけで送信できるようにしたい。
- 送信側は基本的に移動しない（設置場所固定）。位置は「どこから送ったか」が分かれば十分。

## 決定

- 起動時に**動作モード（受信 RX / 送信 TX）を選ばせる**。TX の場合は続けて**送信間隔**（1, 2, 3, 5, 13, 34, 55 秒。既定 3 秒）を選ぶ。間隔は送信中もメニューから変更できる。
- 送信内容は `tx_app.py` の周期送信と同一: **固定送信モード、宛先アドレス 0・チャンネル 0**、ペイロード `SEQ=000001,TS=<ローカル時刻>,MSG=TEST\n`。値は `TxConfig` の定数とし、UI からは変更しない。
- 新しいサービスは作らず、既存のサービスにモードを持たせる（USB 接続・通知・WakeLock・保存先・画面との橋渡しを共用）。
  - RX / TX 共用になるため、`RxService` → **`LoggerService`**、`RxHub` → **`LoggerHub`** に改名する（ADR-0002〜0011 は旧名のまま記述している）。
  - 送信ペイロード生成・送信周期・間欠測位の判定は `core/TxCore.kt`（Android 非依存、JVM 単体テスト対象）。
  - 周期書き込みは `usb/SerialTransmitter.kt`（専用スレッド、絶対時刻基準でドリフトを溜めない）。
- TX のログは**位置関連を最小限**にする。
  - `tx_<stamp>.csv`: 送信 1 件 = 1 行（位置列は空）。位置は「位置を記録」行にのみ付ける。
  - `tx_<stamp>_track.gpx`: 起動時と、以降 **5 分ごとに 1 点**。
  - `_rssi.gpx` は作らない。RSSI ビープも使わない。
- TX は電池消費を抑えるため、**位置の取得自体を間欠にする**（`FixBurstScheduler`）。
  - 起動時と 5 分ごと（測位開始時刻基準）に GPS / ネットワーク位置の取得を開始し、精度 20 m 以内が得られた時点、または 60 秒で打ち切って取得を止める。
  - 記録するのはその間の最良精度の位置 1 点。取得開始時に返る古い位置（30 秒超）は使わない。60 秒で何も得られなければ WARN を出して次回に回す。

## 理由

- RX と TX で USB・通知・権限・保存先・画面の大部分が共通で、サービスを分けると重複が大きい。
- `tx_app.py` と同じ形式で送れば、受信側（Android の RX モード / `rx_app.py`）は変更なしで SEQ 欠落推定・TS 確認ができる。
- 送信側は移動しないため、GPS 1 秒ごとの軌跡や送信地点ごとの記録は冗長。

## 結果

- [ADR-0001](0001-receive-only-logger.md)（受信専用）は本 ADR により置換。E220 のレジスタ設定を持たない点は従来どおり。
- 宛先アドレス・チャンネル・メッセージを変えるにはビルドし直しが必要。
- USB 未接続中の周期は送信せず SEQ も進めない。USB 接続直後に 1 回送信し、そこから周期を数える。
- 書き込みタイムアウトは WARN を出してポートを開いたまま次周期で再試行し、その他の書き込みエラーは USB 切断として扱う。
- TX の GPS 稼働は 5 分あたり数秒〜最大 60 秒になる。屋内など GPS が取れない場所では毎回 60 秒動くため、効果は屋外設置時の方が大きい。
- 測位の合間は画面の GPS ステータスが `GPS: 停止 次回m:ss` になる。

## 検討した代替案

- **TxService を別に作る**: 責務は明確になるが、USB 接続・通知・WakeLock 等の処理がほぼ重複する。
- **アドレス・チャンネル・メッセージを画面で設定**: 普段の運用は固定値のみで、起動時の操作が増えるだけになる。
- **TX でも送信 1 件ごとに位置を付ける**: 送信場所は固定のため情報量が無く、ログが冗長になる。
- **TX でも GPS を常時取得し、記録だけ間引く**: 実装は単純だが、GPS を動かし続けるため電池消費が RX と変わらない。
- **GPS の要求間隔を長くする（例: 5 分）だけ**: 端末によっては GPS が起動したままになり、確実に止まる保証がない。明示的に開始・停止する方が確実。
